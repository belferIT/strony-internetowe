# Lekcje 63–64. Projekt końcowy: własna strona na GitHub Pages

<p class="lekcja-meta">Dział: Podsumowanie · 2 × 45 min + praca własna · Efekty: INF.03.3 (6), (8) · <span class="zakres zakres-gw">★ poza egzaminem</span></p>

## Cel projektu

Tworzysz i publikujesz własną stronę na wybrany temat, wykorzystując wszystko, czego nauczyłeś/nauczyłaś się w tym roku. Strona trafia do Twojego portfolio na GitHubie.

## Przykładowe tematy

Strona o hobby lub klubie sportowym, przewodnik po okolicy, portfolio z pracami z lekcji, strona fikcyjnej firmy (kawiarnia, warsztat, schronisko), mini-gra w przeglądarce, kalkulator lub quiz.

## Wymagania obowiązkowe

1. Co najmniej **3 podstrony** połączone wspólnym menu.
2. Semantyczny HTML5, poprawny w walidatorze W3C (HTML i CSS bez błędów).
3. Jeden zewnętrzny arkusz stylów, wspólny dla wszystkich podstron.
4. Układ strony zbudowany flexboxem lub gridem.
5. Strona responsywna: działa poprawnie na szerokości 375px i 1280px.
6. Co najmniej 3 obrazy przygotowane w programie graficznym (skalowanie, kompresja), z tekstami alternatywnymi.
7. Co najmniej jeden formularz lub element interaktywny w JavaScript.
8. Własne logo w formacie SVG.
9. Uzupełnione `title` i `meta description` na każdej podstronie.
10. Strona opublikowana w GitHub Pages, w repozytorium plik `README.md` z opisem projektu i linkiem do strony.
11. Wszystkie materiały (zdjęcia, ikony, czcionki) własne lub na wolnej licencji, ze źródłami podanymi w stopce lub w `README.md`.

## Wymagania dodatkowe (do wyboru, na wyższą ocenę)

- tryb ciemny ze zmiennymi CSS,
- animacje lub przejścia CSS,
- dane pobierane z pliku JSON lub API (`fetch`),
- zapamiętywanie danych w `localStorage`,
- wynik Lighthouse co najmniej 90 w każdej kategorii.

## Wzajemna recenzja (lekcja 63)

Zamieńcie się w parach linkami do stron. Sprawdź stronę kolegi lub koleżanki według listy wymagań obowiązkowych. Zapisz trzy rzeczy, które są dobre, i jedną, którą warto poprawić.

## Prezentacja (lekcja 64)

W 3 minuty pokaż: temat i dla kogo jest strona, najciekawszy fragment kodu, jedną trudność i sposób, w jaki ją rozwiązałeś/rozwiązałaś.
